Embora este capítulo não seja específico do FreeCAD, ele é fornecido aqui para ajudar desenvolvedores e revisores de código a garantir
um código limpo e de fácil manutenção. As práticas apresentadas devem ser tratadas como receitas culinárias: você pode brincar com elas,
alterá-las, mas toda mudança deve ser pensada e intencional.

Embora esta diretriz possa não ser seguida de forma consistente em toda a base de código existente, aderir a estas práticas
daqui em diante ajudará a melhorar a qualidade geral do código e a tornar as contribuições futuras mais fáceis de manter. Considere-a
uma inspiração para um futuro melhor.

## Para desenvolvedores

Se você é desenvolvedor e quer ler o que consideramos um bom código, consulte as práticas mencionadas abaixo. Estas diretrizes
tentam definir o que é um bom código e como ele deve ser escrito.

- Para C++, consulte as [práticas de C++](../cpp)
- Para Python, consulte as [práticas de Python](../python)

## Para revisores

Para as revisões, é bom ter um conjunto de regras concretas e fáceis de seguir. Se você quer aprender a revisar código, ou
simplesmente quer saber como verificamos o código, consulte o [guia do revisor](../review).
